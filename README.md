# dsh-memory-manager

DeepSeek Harness 长期记忆管理插件。通过 Web 面板和 Agent 工具管理跨会话的用户偏好、项目背景与重要事实。

## 功能

- **记忆管理**：新增、编辑、删除、搜索、筛选、排序和分组；支持重复与冲突审阅。
- **项目隔离**：区分全局记忆与项目记忆，Agent 只读取全局及当前项目内有效、可见的记录。
- **常驻记忆**：重要事实优先提供给 Agent，使用独立字符预算。
- **隐藏与恢复**：记录保留在管理界面中，但不再从记忆库提供给 Agent。
- **来源与有效期**：保存用户原句、来源引用、发生时间、适用条件及生效区间。
- **用户画像**：由 Agent 将已有事实整理成 Markdown 摘要，支持全局与分项目画像。
- **自动沉淀**：按对话轮数提取候选事实，经用户确认后入库。
- **全局规则**：查看和编辑 `~/.dsh/AGENTS.md`，保存前预览差异、确认并备份。
- **导入导出**：JSON 整库备份、合并导入和替换导入，写入前可预览变化。
- **入口配置**：记忆面板可显示在侧边栏、DSH 设置页或两处。

## 安装

插件由宿主端和 Web 客户端组成。宿主端只依赖 Node 内置模块，客户端使用 DSH 提供的 React，无需单独构建。

支持通过绝对路径挂载到目标 profile。在该 profile 的 `cordis.patch.yml` 中添加：

```yaml
- insert:
    - id: memory
      name: 'file:///D:/path/to/dsh-memory-manager/lib/index.js'
```

挂载后重启 DSH。也可以使用仓库提供的安装辅助脚本：

```bat
node install.mjs --profile "%USERPROFILE%\.dsh\profiles\web\cordis.patch.yml"
```

默认只打印配置预览，不修改文件。确认后加 `--write` 写入，脚本会先备份原配置。

> 包名是 `dsh-memory-manager`，运行时标识和数据目录是 `dsh-memory`。请勿通过改名数据目录来更新插件，否则已有记忆将无法被找到。

## 快速上手

1. 打开侧边栏或 DSH 设置中的「记忆」。
2. 点击「+ 新增记忆」，或在对话中让 Agent 记住一条长期事实。
3. 为项目事实明确指定项目归属，为重要事实设置常驻；不希望 Agent 读取的记录可以隐藏。
4. 在「画像」中选择范围，并在相应会话中让 Agent 生成或更新画像。
5. 在「设置」中调整注入方式、自动沉淀、入口位置，或导出备份。

面板包含「记忆 / 画像 / 全局规则 / 设置 / 说明」五个标签。新增、编辑和重复与冲突审阅使用弹窗。

### 记忆类型与格式

记忆类型用于区分内容：

| 类型 | 含义 |
|---|---|
| `semantic` | 稳定事实、长期偏好 |
| `episodic` | 具体事件或经历 |
| `procedural` | 操作流程、行为方式 |

格式用于组织与呈现字段：

| 格式 | 适合内容 | 特点 |
|---|---|---|
| Simple Notes | 简短偏好、单条事实 | 直接呈现自然语言 |
| Enhanced Notes | 经历、背景、叙述 | 保留段落上下文与类型 |
| JSON Cards | 联系信息、项目属性等结构化资料 | 类别 → 子类别 → 字段值 |
| Advanced JSON Cards | 人物、关系及需要消歧的事实 | 增加主体、关系和叙事背景 |

实际格式按以下顺序确定：**记录自身设置 → 第一条匹配规则 → 全局默认**。不同格式共用同一份记录，切换格式不会清空已有字段；它们不是四套独立的存储或检索引擎。

### 项目归属

项目身份来自**会话创建时的绝对目录**，规范化后生成 `projectId`。Windows 路径统一大小写，切换工作子目录不改变归属；不同项目根目录或工作树分别隔离。

- Agent 的注入、搜索、列表、提取已有事实上下文和项目画像只使用**全局 + 当前项目**的有效可见记录。
- 无法取得会话项目上下文时，只读取全局记忆；Agent 不能指定任意项目 ID 越界读取。
- 没有 `projectId` 的旧项目记录仍可管理，但不会提供给 Agent。可在「项目与事实状态筛选」中查看待认领记录，编辑时选择项目或填写项目绝对路径，保存即确认归属。
- 目录搬迁后需要明确调整记录归属，插件不会自动猜测新旧目录的关系。

### 来源、时间与冲突

卡片的「查看依据」可显示保存的用户原句、来源会话、消息与事件位置、观察时间及确认方式，也可展开合并记录的关联来源。

没有来源的旧记录不会被视为已经核实。插件不自动读取整段原会话；原会话可能未加载或已删除。手动修改事实后，原句只作为历史依据，不能自动证明改写后的陈述。

在高级选项中可以设置：

- **发生时间**：事实或事件发生的时间，与创建、修改时间不同。
- **生效和失效时间**：适用区间为 `[validFrom, validUntil)`；未设置的一端不作限制。
- **主体、关系与适用条件**：例如“父亲的心脏科医生”“仅工作日使用”。
- **事实状态**：当前有效、历史记录、待确认冲突、已被取代。

时间输入采用浏览器本地时间，存储为 UTC 毫秒。未生效、过期、历史、被取代及待确认冲突的记录不会提供给 Agent。

相同项目、主体、关系、条件和结构化路径下的当前多值事实会暂停提供给 Agent，等待审阅。对象或条件不同、有效期不重叠的事实可以并存。用户可以明确选择一条记录取代其他记录，旧记录会保留；插件不会仅凭更新时间决定哪条事实正确。

精确重复项可以合并标签，其余副本转为历史记录并保留来源引用。来源隐藏、删除或出现冲突时，相关派生记录也会受到读取限制。冲突检测基于结构化规则，不是通用自然语言语义判断。

### 常驻、隐藏与自动注入

- **常驻**：在独立预算内优先注入，不占普通记忆条数，不受普通记忆自动注入开关影响。
- **普通明细**：按当前用户问题进行 BM25 风格词法检索，结合重要性与时效排序，按完整条目装入字符预算。
- **隐藏**：阻止记录从记忆库再次进入自动注入、Agent 搜索与列表、画像及提取已有事实上下文。隐藏优先于常驻。

管理面板默认显示全部记录，包括隐藏和历史记录。隐藏、事实状态和有效期相互独立，**恢复可见不等于恢复有效**。

注入模式可选择：

| 模式 | 行为 |
|---|---|
| 摘要 | 使用范围匹配且可用的画像；不可用时回退相关明细 |
| 明细 | 提供与当前任务相关的事实条目 |
| 混合 | 提供相关明细及可用画像 |

宿主会记录注入快照。插件在下一步撤回旧快照的活动上下文，再提供当前有效内容，原始事件留作审计。**隐藏不能抹去模型已经读过的信息、旧工具结果、用户或助手的引用及已生成的会话摘要。**

### 用户画像

全局画像只总结全局事实；项目画像只总结全局及对应项目事实。项目画像须在该项目会话中生成，没有可用项目画像时不会借用其他项目的摘要。

画像由 Agent 通过 `memory_update_profile` 保存，不由插件独立生成。可在对话中提出：

- “仅基于全局记忆更新全局画像。”
- “帮我更新当前项目画像。”

为避免旧事实或其他项目的信息混入摘要，Agent 应遵循以下流程：

1. 全局画像先调用 `memory_list(scope=global)`；项目画像先调用不带 scope 过滤的列表，读取全局及当前项目事实。
2. 根据返回的事实生成摘要，保留人物、时间、条件和否定信息；结果截断时不能声称已读完整记忆库。
3. 保存时提交目标范围、最新 `revision`、`snapshot` 和实际引用的非空 `sourceIds`。

只有范围快照匹配、来源记录当前有效时，画像才可注入。缺少快照或来源的兼容保存仅作为待更新草稿，供管理查看。来源引用用于校验范围和有效性，不等于摘要语义已经被核实。

隐藏、修改、冲突或有效期届满会使相关画像不可注入。版本校验采用乐观并发，不阻塞隐藏操作；旧快照不能跨宿主重启重用。

### 自动沉淀

启用后，插件按设置的轮数间隔分析对话，提取最多 3 条候选事实。候选包含用户原句，用户确认后才正式入库；不会自动设为常驻，也不会自行删除旧事实。

提取需要宿主提供 LLM 服务及可用路由。可配置 `extractProvider` 和 `extractModel`，未指定时尝试使用已观察到的会话模型路由。待确认队列位于宿主内存中，宿主重载后不会保留。

### 全局规则

「全局规则」编辑固定位置的 `~/.dsh/AGENTS.md`，适合保存希望 Agent 长期遵守的工作规范，例如“修改代码后运行相关测试”。DSH 宿主按会话加载该文件，独立于插件的记忆注入开关。

保存前需要预览差异并确认完整内容，插件会核对文件是否变化、备份原内容，再写入新内容。Agent 写入工具同样要求先取得用户对具体内容的明确确认。

全局规则不会与记忆自动同步。隐藏记忆或关闭记忆注入，不会停用已复制到全局规则中的内容；规则也不能覆盖更高优先级的系统和安全要求。

### 导入与备份

在「设置」中可以导出整库 JSON，包含记忆、设置、项目目录表和画像。

导入时先预览新增、更新、保留和无效记录的数量，再选择：

- **合并**：按记录 ID 合并，保留未被替换的记录。
- **替换**：替换整库内容；写入前自动备份当前状态。

无效记录会阻止正式导入。导入后的画像需要重新确认有效性，不能直接作为可信摘要使用。

## 数据存放

默认位置：

- Windows：`%APPDATA%\dsh-memory\memory.json`
- 其他系统：`~/.local/share/dsh-memory/memory.json`

可以通过 `DSH_MEMORY_DIR` 覆盖记忆数据目录。全局规则使用固定的 `~/.dsh/AGENTS.md`，不随记忆数据目录改变。

存储使用 JSON，版本为 `1`。主要内容为：

| 内容 | 用途 |
|---|---|
| `settings` | 格式、注入、自动沉淀、入口等设置 |
| `memories` | 事实记录及来源、项目、状态和时间字段 |
| `projects` | 已登记项目的 ID、名称与目录 |
| `profile` | 全局画像 |
| `profiles` | 按项目 ID 保存的画像 |

记录在内存中更新后防抖写盘，使用临时文件和原子替换保存。加载失败时进入只读恢复状态，不覆盖损坏的原文件。

> 数据、导出文件和备份均为本地明文，请勿保存密码、token 或密钥。隐藏不是加密，也不是删除。

## Agent 工具

| 工具 | 作用 |
|---|---|
| `memory_write` | 新增一条长期事实，支持类型、范围、标签、重要性、常驻、来源原句、时间与条件等字段 |
| `memory_search` | 搜索有效可见的记忆；可按 global/project 过滤，返回版本与范围快照 |
| `memory_list` | 按更新时间列出有效可见的记忆；返回版本、范围快照和是否截断 |
| `memory_forget` | 按 ID 删除允许读取的记忆；不能删除隐藏、其他项目或无效记录 |
| `memory_update_profile` | 保存全局或当前项目的 Markdown 画像，校验版本、范围快照与来源 |
| `memory_read_agents_md` | 读取全局规则 |
| `memory_write_agents_md` | 整体替换全局规则，要求先取得用户对完整内容的明确确认 |

工具不提供读取隐藏记忆的参数，也不允许指定任意项目 ID。管理面板可以管理全部记录，不受 Agent 的读取范围限制。

## HTTP 接口

接口通过 DSH 的 owner Peer 权限控制访问，浏览器使用同源凭据。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/memory/state` | 读取管理状态、全部记录、项目与画像 |
| POST | `/api/memory/rpc` | 管理记忆、设置、候选、导入预览、项目登记及记录合并/取代 |
| GET | `/api/memory/export` | 下载整库 JSON |
| GET / POST | `/api/memory/profile` | 读取或保存画像；支持 `projectId`、版本、范围快照与来源校验 |
| GET / POST | `/api/memory/agents-md` | 读取或保存全局规则 |
| GET | `/api/memory/pending` | 读取待确认候选 |

RPC 请求格式为 `{ "action": "...", "payload": { ... } }`，支持：

```text
state / add / update / delete / clear / settings / search
export / preview-import / import / approve / reject
register-project / supersede / merge-duplicates
```

管理 RPC 的 `search` 默认不包含隐藏记录，显式设置 `includeHidden: true` 才包含。

## 限制与隐私

- 检索使用 BM25 风格词法匹配，不是向量语义检索。同义表达可能漏检，应调整关键词或进一步澄清。
- 列表工具有数量上限且没有分页，返回 `truncated=true` 时不能将结果视为整库。
- 自动沉淀会把对话内容发送给所选模型服务；禁存敏感信息的提示词不能替代外发前脱敏。
- 隐藏只限制从记忆库再次读取。用户在对话中重新表达相关事实时，仍可能产生新候选；同范围、主体和条件下的精确同文会去重，改写不保证去重。删除记录也不能保证未来不再出现。
- 确认来源引用不等于确认事实真实；摘要和自动提取结果仍需审阅。
- 同一数据文件不应由多个宿主进程并发写入。测试实例需要单独设置 `DSH_MEMORY_DIR`，仅设置 `DSH_HOME` 不能隔离记忆数据。

## 测试

测试使用临时数据目录和合成案例，不依赖真实记忆库。

```sh
node --check lib/index.js
node --check lib/shared.js
node --check lib/client.js
node test/p0-tests.mjs
node test/p1-tests.mjs
node test/p1-client-tests.mjs
node test/phase1-tests.mjs
node verify-p0-fixes.mjs
node test/phase1-eval.mjs
node test/phase1-live-eval-tests.mjs
```

评测覆盖基础回忆、跨会话检索以及关联与澄清所需的证据。默认不调用真实模型，报告检索指标、注入开销和读取边界检查结果，不代表真实模型的回答或主动服务能力。

如需测试真实模型的多步只读工具调用，显式配置以下环境变量：

| 变量 | 用途 |
|---|---|
| `DSH_MEMORY_EVAL_LIVE=1` | 启用真实模型评测 |
| `DSH_MEMORY_EVAL_BASE_URL` | 用户选择的 OpenAI 兼容服务地址，例如服务的 `/v1` 入口 |
| `DSH_MEMORY_EVAL_MODEL` | 模型名称 |
| `DSH_MEMORY_EVAL_API_KEY` | 可选 API 密钥 |

然后运行 `node test/phase1-eval.mjs <报告路径>`。不配置时不会选择默认外发端点；没有密钥时不附 Authorization。报告中的回答模式检查不能替代独立语义审核，合成测试结果也不代表真实任务总体效果。

已有 DSH 测试实例可运行浏览器检查：

```sh
node check-demo.mjs "<实例输出的带 token URL>"
```

请勿把访问 token、API 密钥、真实记忆、截图或本地过程文档提交到仓库。
